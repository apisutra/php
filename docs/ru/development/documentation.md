# Сопровождение документации <a id="section-1"></a>

Публичная документация обслуживает автора SDK и пользователя готового клиента.
Изменение ядра описывается отдельно в `docs/ru/development/`. Инструкции ИИ-агенту находятся
в [.agents/documentation.md](../../../.agents/documentation.md).

## Владение содержанием <a id="section-2"></a>

| Слой | Что хранить |
| --- | --- |
| `docs/ru/start/` | Разборы задач; отдельный вход и карта выбора возможностей для агента |
| `docs/ru/guides/` | Практика со ссылками на контракт и исполняемый образец |
| `docs/ru/reference/` | Один полный владелец параметров, приоритетов и ограничений |
| `docs/ru/glossary/` | Короткое определение и ссылка на владельца |
| `docs/example/` | Поставляемые исходники, фикстуры и запуск |
| `docs/ru/development/` | Руководство разработчика ApiSutra, устройство ядра и проверки checkout |

У ИИ-агента два входа: [использование пакета](../start/agent.md) и
[изменение ApiSutra](../../../.agents/README.md). Первый даёт контекст, условия выбора
и [карту возможностей](../start/agent-capabilities.md), второй — процедуры и правила
репозитория. Пользовательская карта не задаёт обязательной последовательности.
Оба входа ссылаются на единых владельцев контрактов в справочнике.

## Изменить контракт <a id="section-3"></a>

Сверьте декларацию с `src/` и поведение с целевым тестом. Измените тематического
владельца, затем примеры и короткие ссылки из остальных слоёв. Не копируйте таблицу
приоритетов в glossary, guide и attributes. Справочник атрибутов задаёт сигнатуру
декларации и ссылается на поведение в тематическом разделе.

Для публичных PHP-имён используйте явный реестр
[docs-api.json](../../../tests/Support/docs-api.json). Проверка Reflection сверяет классы,
публичность, параметры и типы, не создавая пользовательские object-default значения.
Для атрибутов отдельно сравнивается текст конструктора и опубликованная сигнатура: default
не вычисляется, но изменение его выражения требует обновить документацию.
Этот реестр не доказывает семантику: побочные эффекты defaults с `new`, приоритеты и ограничения
подтверждаются исходниками и наблюдаемыми сценариями.

## Исполняемые примеры <a id="section-4"></a>

Классы примера находятся в отдельных PSR-4 файлах с namespace. Руководство ссылается
на эти файлы. Smoke исполняет опубликованный файл, включая архив без require-dev;
копировать пример внутрь теста нельзя. Фрагмент справочника может показывать
отдельный вызов, но должен обозначать внешние переменные и требуемый контекст.

Laravel-пример выполняется с реальными зависимостями отдельно. Для обычной проверки
используйте fake: внешнее API и credentials не должны требоваться для чтения quickstart.

## Перенести страницу <a id="section-5"></a>

При переносе сохраните полезное содержание и обновите ссылки текущего комплекта,
включая реестр деклараций. Удалите прежнюю страницу и неиспользуемые якоря.
При перемещении раздела разработки обновите исключения Git/Composer архивов
и классификацию документов в проверяющих инструментах.
Каждая опубликованная страница содержит актуальное руководство, справку или индекс.
При перемещении страницы обновляйте публичные ссылки; сохраняйте актуальную структуру документации.

Лимиты строк: корневой README с тремя примерами и группами возможностей 240, индекс 150,
маршрут 200, guide 300, reference 320, glossary 180,
development 220; дополнительно 24 KiB на файл. История изменений и версионные
release notes исключены. Если тема не помещается, разделите её по самостоятельным
задачам; не создавайте «часть 1/2».

## Проверки <a id="section-6"></a>

```bash
composer check-docs
git diff --check
```

Этих проверок достаточно для текстовых изменений. Изменённые PHP-примеры также требуют
`composer analyse-docs` и выполнения затронутого сценария. Запускайте `composer check-package`
при изменении состава дистрибутива, путей или установки, а также при подготовке выпуска.
`composer check-docs` уже запускает тесты проверяющего инструмента; повторять их отдельно не нужно.

`check-docs` проверяет локальные пути, якоря, reference-style ссылки, размер,
достижимость страниц, запрещённые зависимости публичного комплекта, страницы-переходы,
блоки прежних разделов, пустые определения словаря, реестр API и опубликованные
примеры. `--report` сохраняет подробный JSON;
`--navigation-only --distribution` проверяет документацию распакованного архива.

В [Docs CI](../../../.github/workflows/docs.yml) выполняются `composer check-docs` и
`composer analyse-docs` на PHP 8.4. Workflow запускается на push, pull request и
вручную; техническая ветка `badges` исключена из push. Изменения src тоже запускают
проверку соответствия документации API. Бейдж Docs CI в README показывает результат
push-проверки ветки master; бейдж docs ведёт к пользовательской документации.

Неблагоприятные случаи проверяющего инструмента закреплены отдельными тестами.
Внешние веб-страницы, содержательная полнота API, смысл SQL/JSON/команд и корректность
всех контекстных PHP-фрагментов автоматически не доказываются: для них нужна
редакционная сверка и целевые проверки. Совпадение числа файлов не заменяет эту работу.

Когда проверка архивов нужна, `check-package` по умолчанию берёт HEAD, `--staged` — Git index.
Выберите нужные изменения, при необходимости через временный `GIT_INDEX_FILE`, чтобы
сохранить staging пользователя, и укажите проверенный tree в результате. Отдельный файл
отчёта необязателен. Git и Composer архивы должны совпасть и установить runtime-зависимости.

## Языковые редакции <a id="section-7"></a>

Основной язык — английский, обязательные редакции — английская и русская.
`docs/translations.json` связывает стабильный ID страницы, её тип, область поставки
и пути редакций. Корневые README, CONTRIBUTING и CHANGELOG имеют явные соответствия.
Новый необязательный язык добавляется в `languages`; отсутствующий перевод отмечается
в переключателе как английская замена. Для обязательного языка замена недопустима.

При изменении контракта обновите обе редакции и отдельно сверьте условия, отрицания,
приоритеты, ограничения и примеры. После сверки явно запишите в `reviewed` SHA-256
основной страницы и перевода; нормализуются только переводы строк. Изменение любой
стороны делает запись устаревшей. CI проверяет хеши, но не обновляет их и не доказывает
качество перевода. Простое обновление хешей без просмотра смысла недопустимо.

Переключатель задаётся по ID документа, обычные ссылки сохраняют текущую локаль.
Явные английские якоря одинаковы у переводов и не зависят от текста заголовка.
`docs/example/` и fixtures общие; комментарии исполняемых PHP-файлов не переводятся.
Поясняющие комментарии внутри Markdown переводятся на язык страницы. Имена PHP,
протокольные литералы, команды и точный вывод остаются прежними.

Пользовательские редакции и реестр входят в Git/Composer dist. Разделы
`docs/*/development/`, CONTRIBUTING, AGENTS и `.agents/` исключены для всех языков.
Навигация дистрибутива проверяется с `--navigation-only --distribution`;
внешние ссылки на документацию разработки проверяются в checkout.
