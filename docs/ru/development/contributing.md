# Участие в разработке ApiSutra <a id="section-1"></a>

Подготовка окружения, карта механизмов и проверки изменений ядра, тестов,
документации и инструментов — в [руководстве разработчика](README.md).
Для ИИ-агента предусмотрен [отдельный вход с правилами репозитория](../../../.agents/README.md).
Для создания SDK внешнего API начните с [пользовательской документации](../start/create-sdk.md).

## Описать предложение или проблему <a id="section-2"></a>

Укажите, какую задачу пользователя решает изменение. Для дефекта приложите
минимальный сценарий, входные данные, ожидаемый и фактический результат,
версию PHP и пакета. Используйте обезличенные данные без ключей доступа.

Объясните, почему механизм относится к общему ядру, и какие существующие
публичные возможности уже были проверены. Особенности протокола одного API
реализуются в SDK его провайдера.

## Подготовить изменение к рассмотрению <a id="section-3"></a>

В описании изменения укажите:

- проблему и итоговое поведение с точки зрения пользователя;
- затронутые контракты и совместимость, необходимые действия при обновлении;
- выполненные проверки и их результаты, существенные ограничения проверки;
- ссылки на обновлённые руководства и примеры.

Команды проверок принадлежат [руководству по тестированию](testing.md),
правила документации — [её сопровождению](documentation.md).
Описание должно быть понятным без чтения истории обсуждения.
