# Разработка ApiSutra <a id="section-1"></a>

Техническое руководство по изменению самого `apisutra/php`: ядра, тестов,
зависимостей, документации и CI. Инструкции для ИИ-агента находятся отдельно
в [.agents/README.md](../../../.agents/README.md).
Для разработки SDK внешнего API используйте [пользовательский маршрут](../start/create-sdk.md).
Подключение публичных casts, hooks и extensions также относится к использованию пакета.

## Начать работу <a id="section-2"></a>

1. Изучите [архитектуру](architecture.md) и документ нужного механизма из таблицы ниже.
2. Сверьте ожидаемое поведение с [публичным справочником](../reference/README.md),
   текущими исходниками и тестами. Уточните границы задачи и совместимость.

При передаче задачи агенту укажите желаемый результат, наблюдаемый сценарий,
ограничения и способ проверки. Агент выбирает применимые правила в `.agents/`;
для работы над внешним SDK есть [пользовательский вход](../start/agent.md).

## Подготовить checkout <a id="section-3"></a>

Нужны Git, PHP 8.4+ и Composer. Из корня репозитория:

```bash
composer install
composer test
```

Обычные тесты используют локальные зависимости, им не нужны внешнее приложение
и база данных. Проверки документации требуют Python 3.9+; Laravel и Redis имеют
отдельные стенды. Команды и условия — в [тестировании](testing.md).

## Выполнить изменение <a id="section-5"></a>

1. Зафиксируйте наблюдаемое и ожидаемое поведение. Общий механизм остаётся
   в ApiSutra, особенности конкретного API — в SDK провайдера.
2. Измените затронутый механизм, сохраняя его связи и публичные контракты.
   При изменении поведения проверьте соответствующие сценарии, включая ошибки.
3. Обновите документ, которому принадлежит изменённый контракт, и зависимые примеры.
   При изменении совместимости опишите действия потребителя в примечаниях к выпуску.
4. Выполните применимые [проверки](testing.md). Укажите результат, ограничения
   проверки и последствия для пользователя в описании изменения.

Требования к описанию вклада — в [CONTRIBUTING](contributing.md).

## Поставка документации <a id="section-6"></a>

Пользовательские README, руководства, справочник и примеры входят в Git/Composer
архивы. `docs/*/development/`, `CONTRIBUTING.md`, `.agents/` и тестовый
стенд доступны в checkout и исключены из архивов. Поэтому из пользовательских
страниц ссылки на разработку ведут в репозиторий по полному URL.

`composer check-package` проверяет состав обоих архивов, установку без dev-зависимостей
и standalone smoke. Для изменений рабочего дерева порядок проверки описан
в [тестировании](testing.md#section-2).
