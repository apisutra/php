# Создать SDK внешнего API <a id="section-1"></a>

Результат маршрута — SDK с работающей первой операцией, воспроизводимыми тестами
и явной картой дальнейшего покрытия. Учебная реализация — [Records SDK](../examples/sdk.md).

## Что подготовить <a id="section-2"></a>

Нужны версия документации API, базовые адреса, способ авторизации, несколько
обезличенных ответов и список нужных операций. Отдельно запишите неподтверждённые
условия: не выводите лимиты, форматы ошибок или идемпотентность из названия endpoint.
[Исследование API](../guides/sdk/analysis.md) перечисляет факты, которые надо собрать.

## Порядок работы и приоритеты <a id="section-3"></a>

1. **Определите объём.** Выберите одну полезную операцию, её успешный ответ и ошибку.
   Остальные операции внесите в карту покрытия; сначала добейтесь рабочего сквозного пути.
2. **Спроектируйте SDK.** Выделите клиент, ресурсы и локальные DTO операции по
   [правилам владения типами](../guides/sdk/design.md). Несколько сервисов или версий
   выделяйте при реальном различии протоколов и конфигураций.
3. **Соберите клиента.** Явно задайте конфигурацию и транспорт через
   [standalone](../guides/integration/standalone.md) или
   [Laravel-интеграцию своего SDK](https://github.com/apisutra/laravel/blob/master/docs/ru/guides/sdk/laravel.md). Подтвердите auth и базовый URL.
4. **Опишите запрос.** По [первой операции](../guides/sdk/first-operation.md) задайте
   HTTP-метод, путь, query/body и `Returns`. Локальная проверка входа должна предшествовать HTTP.
5. **Опишите DTO.** Выберите [plain-модели или атрибуты](describe-dto.md). Сначала
   зафиксируйте mapping, присутствие, null и форму; затем преобразования и расширения.
6. **Проверьте результат.** Запустите фикстуры успешного ответа, ошибки и дрейфа DTO
   по [руководству тестирования](../guides/testing/unit.md). Проверьте исходящий payload.
7. **Подключите сложное поведение по фактам API.** Пагинация, await, retry, кеш и
   загрузка файлов добавляются вместе с их отдельными сценариями и пределами.
8. **Расширьте и выпустите SDK.** Пройдите [покрытие](../guides/sdk/coverage.md),
   затем [документацию и выпуск](../guides/sdk/release.md).

## Когда задача выполнена <a id="section-4"></a>

Потребитель может установить SDK, создать клиента из документированной конфигурации,
вызвать операцию и получить типизированные данные либо объяснимую ошибку. Тесты не
требуют настоящего API; live-проверки выделены отдельно. Неподдержанные возможности
и неподтверждённые ограничения явно перечислены, секретов в фикстурах нет.

Результат передаётся одинаково человеку и агенту: исходники, команды проверки,
наблюдаемый результат, ограничения и карта следующего покрытия.

## Следующая операция <a id="section-5"></a>

[Добавить операцию](add-operation.md) использует уже принятую структуру и правила.
Не переносите особенности внешнего API в ядро ApiSutra: поддержанные
[расширения](../reference/extensions/README.md) позволяют реализовать их в SDK.
