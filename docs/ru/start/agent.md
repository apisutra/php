# Агенту, который использует ApiSutra <a id="section-1"></a>

Область: SDK внешнего API, приложение с готовым SDK и расширения через публичные
casts, providers, hooks, transport или классы результата. Изменение самой ApiSutra
имеет [отдельный вход](https://github.com/apisutra/php/blob/master/.agents/README.md).

## Как выбирать решение <a id="section-2"></a>

[Карта возможностей](agent-capabilities.md) связывает задачи с механизмами,
условиями применения и владельцами контрактов. Выбирайте нужные разделы по задаче;
порядок разделов не задаёт порядок работ. Наличие возможности не требует её включать.

Решение определяется целью пользователя, существующим SDK, установленной версией
ApiSutra и подтверждённым контрактом внешнего API. Примеры показывают варианты
решения; структуру и стиль определяют правила проекта, в котором работает агент.

## Границы ответственности <a id="section-3"></a>

| Слой | Что ему принадлежит |
| --- | --- |
| ApiSutra | Общие механизмы запросов, преобразований, исполнения, результатов и расширений |
| SDK провайдера | Адреса, операции, auth-схема, модели, форматы ошибок и особенности конкретного API |
| Приложение | Credentials, окружение, хранилища, сценарии использования и бизнес-решения |

Собственный cast, hook или класс результата в SDK — использование публичного API,
а не повод менять ядро. Возможность пакета оценивается по контракту и сценарию,
а не по наличию ровно такого примера в документации.

## Основания для выбора <a id="section-4"></a>

- **Существующая структура.** Продолжайте принятую организацию SDK. Базовый DTO,
  профиль, фабрика, каталог или дополнительный слой нужны при конкретной пользе;
  учебный пример не обязывает создавать их все.
- **Фактура API.** Типы, nullable, пагинация, повторы и auth выводятся из спецификации
  и наблюдаемых ответов. Предположения обозначаются отдельно; неизвестное поведение
  провайдера не становится гарантией SDK.
- **Подходящий механизм.** Декларации подходят для штатного отображения данных;
  свой обработчик — для поведения за их границами.
  Подробные приоритеты и ограничения принадлежат [справочнику](../reference/README.md).
- **Совместимость.** Сигнатуры должны соответствовать установленной версии пакета.
  Смена представления DTO, политики ошибок или способа отправки требует учитывать
  существующих потребителей SDK.
- **Доказательство результата.** Проверки определяются изменением: например, форма
  HTTP-запроса, преобразование ответа или обработка ошибки. Используйте инструменты
  и команды проекта потребителя; его тестам не нужен внутренний стенд ApiSutra.
  В выводах различайте воспроизведённое поведение, вывод по коду и предположение.
