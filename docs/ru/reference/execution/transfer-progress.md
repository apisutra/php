# Прогресс HTTP-передачи <a id="section-1"></a>

Наблюдение за отправленными/полученными байтами включается через
`withTransferProgress(callable)` у запроса, цепочки исполнения или `RequestOptions`.
По умолчанию выключено; `withoutTransferProgress()` снимает его в копии опций.
Исходный запрос/опции не меняются. Глобального наблюдателя и обязательной настройки
клиента нет.

## Наблюдение передачи <a id="section-2"></a>

Для запроса SDK, уже связанного с клиентом:

```php
use ApiSutra\VO\Http\TransferProgress;

$latest = null;
$handle = $request
    ->withTransferProgress(static function (TransferProgress $progress) use (&$latest): void {
        $latest = $progress;
    })
    ->sendAsync()->wait();

$data = $handle->dataOrFail();
// Читаем/отображаем последний снимок вне callback.
```

Неизменяемый снимок содержит публичные свойства:

| Свойство | Значение |
| --- | --- |
| `trace` | `ExecutionTrace` исполнения, включая идентификаторы исполнения и родителя |
| `attempt` | Фактическая HTTP-попытка внутри исполнения, начиная с 1; включает auth recovery |
| `uploaded`, `downloaded` | Байты этой попытки по счётчикам HTTP-библиотеки |
| `uploadTotal`, `downloadTotal` | Ожидаемые транспортные байты либо `null`, если размер неизвестен |

На каждой попытке счётчики начинаются заново. Снимок не означает завершение: успех
определяется результатом. После внешне завершённой передачи возможен retry.
Multipart и chunked могут включать разметку; gzip-счётчики могут отличаться от размера
сохранённого файла. Это не мера подтверждённой бизнес-обработки или размера исходного файла.

У Guzzle/cURL положительный total сохраняется, нулевой становится `null`, включая
пустое тело с `Content-Length: 0`. Заголовки для различения этих случаев не анализируются.
Нулевые счётчики байтов остаются нулевыми. Появление известного total даёт новый снимок,
даже если байты не изменились. Одинаковые последовательные значения могут подавляться;
частота и финальное уведомление «100%» не гарантируются.

## Callback и жизненный цикл <a id="section-3"></a>

Callback выполняется внутри передачи. В нём нельзя выполнять I/O, вызывать SDK/event loop
или приостанавливать Fiber. Сохраните небольшой снимок в памяти, отображайте/экспортируйте
его вне callback. Это контракт расширения, а не техническая блокировка приостановки.

Любое исключение callback отключает наблюдение этого исполнения, включая следующие
retry. Оно не вызывает отказ запроса и соседних конкурентных передач.
Каждая страница пагинации — отдельное исполнение: тот же callable снова активен
и может ошибиться один раз на страницу. Auth, polling и другие зависимые запросы
автоматически callback не наследуют. Trace и attempt захватываются до отправки;
наблюдение не зависит от текущего контекста callback планировщика.

Cache hit, early return и отказ до отправки не создают прогресса. Штатные MockTransport,
playback и Laravel fake тоже принимают опцию без уведомлений: прикладному коду с этими
fake не нужны ветвления по окружению или искусственные события прогресса.

Отмена/abandon и завершение закрывают получателя попытки; поздние уведомления
игнорируются. История прогресса и отдельные записи audit/log на каждый снимок не копятся.
Состояние ограничено исполнением/попыткой; сохранённые опции запроса могут продолжать
владеть пользовательским callable. Массив всех снимков в приложении добавил бы свою
неограниченную историю.

## Поддержка транспортом <a id="section-4"></a>

Штатный Guzzle/cURL поддерживает sync/async upload/download, включая изолированные
внешние URL. Прогресс передаётся на конкретную отправку без расширения allowlist
изоляции. SDK-наблюдение перекрывает native Guzzle `progress` из defaults на этой
отправке; без SDK opt-in существующая настройка не меняется.

SDK progress вместе с низкоуровневыми настройками `curl` даёт `configuration_error`
до HTTP, включая auth dependency. Граница консервативная, как для потоковых файлов
и изоляции URL: в таком сочетании отказывается даже неконфликтующая raw cURL-опция.

Собственный транспорт и его HTTP-адаптер должны объявить `TransferProgressInterface`
и реализовать `assertSupportsTransferProgress()`. Для получения опций адаптеру нужен
также `HttpClientOptionsInterface`. Без capability opt-in отказывает до auth/cache,
даже при попадании в кеш; без прогресса прежние адаптеры работают как раньше.
Собственный test double тоже объявляет capability. RecordingTransport делегирует
поддержку и опцию, не сериализует callback и события прогресса в кассеты.

Для авторов расширений: `TransportOptions::transferProgress` — nullable closure с четырьмя
сырыми счётчиками в порядке download total, downloaded, upload total, uploaded, в байтах.
Вызывайте его только во время этой отправки. SDK передаёт защищённого получателя,
который владеет trace/attempt и изолирует ошибки приложения. Сохраняйте его при копировании
опций; `effective()` и `withTransferProgress()` это делают. Транспорт не выбирает
идентификаторы, retry-политику или исход исполнения. Fake объявляет capability без счётчиков.

## Запускаемый пример <a id="section-5"></a>

Нужны опциональный пакет `guzzlehttp/guzzle`, ext-curl и `proc_open`. Пример запускает
только локальный HTTP-сервер: binary upload, async download с retry и скачивание
без известного total:

```bash
php vendor/apisutra/php/docs/example/transfer-progress/run.php
```
