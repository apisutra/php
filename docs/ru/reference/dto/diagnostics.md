# Путь ошибки и безопасная диагностика <a id="section-1"></a>

Расширенная диагностика включается также общей HydrationConfig или атрибутами DTO, без внешнего набора. Обнаружение атрибутного ребёнка сохраняет путь родителя; после cast/provider/hook остаётся Boundary либо Unavailable.

## Когда включается SourcePath <a id="section-2"></a>

При явном HydrationConfig или новых декларациях DTO ошибка гидратации дополняется JSON Pointer `sourcePath`,
`sourcePathKind` и `sourceCandidates`. DTO-путь `path` описывает поле DTO.
Точный путь доступен через `context()` и ExecutionResult, автоматические логи используют
`logContext()` с маскированием неизвестных ключей. После пользовательского преобразования
указывается Boundary или Unavailable. [Значения и примеры](diagnostics.md#section-3).
Без config и этих деклараций дополнительные поля sourcePath не включаются.

## Диагностика и входы <a id="section-3"></a>

При включённой расширенной диагностике `HydrationException::context()` содержит `sourcePath`,
`sourcePathKind` и `sourceCandidates`. Старый `path` описывает DTO, sourcePath —
JSON Pointer исходного значения (`~` → `~0`, `/` → `~1`, корень — пустая строка).
Например, ошибка `rows[1].value.record_id` даёт path `items[1].id` и
sourcePath `/rows/1/value/record_id`; unwrap=data добавит соответствующий префикс.

| SourcePathKind | Значение |
| --- | --- |
| Resolved | Точное расположение исходного значения |
| Expected | Отсутствующий primary; возможные пути — sourceCandidates |
| Boundary | Ближайший известный вход cast/provider/hook/computed/aggregate |
| Unavailable | Исходное расположение неизвестно; sourcePath = null |

Автоматический лог вызывает `logContext()`: объявленные сегменты и индексы настоящего
списка сохраняются, неизвестные строковые **и числовые** ключи словаря заменяются `*`.
Точный путь остаётся в исключении и ExecutionResult. Message не включает значения ответа.
После пользовательского преобразования ядро не выдаёт новый путь за исходный.
При Ready без объявленного пути continuation происхождение Unavailable.

Один гидратор клиента используется в Returns (sync/promise), пагинации, CompositeFlow,
await и cached awaitAs. При наборе items-only пагинация также применяет itemsType;
без набора возвращает raw-результат. HTTP cache хранит ответ, поэтому другой
клиент гидратирует cache hit собственными правилами. Handler с ненулевым результатом,
RawResponse и Download обходят гидратацию DTO. [Готовность await](../../guides/recipes/continuation.md)
определяется раньше строгой проверки финального DTO.

Глубина ограничена 512 активными узлами DTO/list, корень считается первым.
Соседние ветви не суммируются. Более глубокий ввод даёт `hydration_depth_exceeded`,
циклическая ссылка PHP-объектов — `cyclic_hydration_input`. Один объект в независимых
ветках допустим. Состояние обхода принадлежит одному корневому вызову и не кешируется.

## Подробная диагностика гидратации <a id="section-4"></a>

Автоматический ERROR log для перечисленных встроенных ошибок содержит
`reason`, `path`, `expected`, `actual`, `httpStatus`, класс запроса (`request`) и
`traceId`. Actual сообщает тип или missing/null, а сообщение не включает исходное
значение. Например, `items[2].price`, expected `float`, actual `array` указывает
нарушенный контракт. Для неизвестных вариантов discriminator `Nested` Skip пропускает элемент, а KeepRaw сохраняет его входные данные.

Если для расследования нужно само значение, прочитайте исходный ответ из результата:

```php
// $request — настроенный запрос SDK-провайдера с объявленным DTO ответа.
$result = $request->send()->raw();
$error = $result->errors->first();
$diagnostic = $error?->context;           // Путь, причина и ожидаемый тип.
$body = $result->response?->body;         // Исходное тело HTTP-ответа без маскирования.
```

`response` и его body доступны при `debug: false`: ошибка гидратации не маскирует
и не пересобирает ответ. SDK не требует нового режима конфигурации или хранилища
диагностических данных. Провайдер может явно сохранить нужный ответ при обработке
результата по своим правилам доступа и маскирования. Raw body и `previous` не являются
очищенным экспортом; не отправляйте их целиком в общий автоматический лог.
Гарантия безопасных сообщений относится к перечисленным встроенным проверкам,
а не к произвольному тексту пользовательских casts/конструкторов.

Дополнение DTO-пути или происхождения создаёт независимую копию диагностики. Итоговое
исключение содержит полный путь; его цепочка `previous` сохраняет первичную ошибку
гидратации, её трассировку и исходную причину, если она есть. Промежуточные копии
диагностики не сохраняются на каждом уровне вложенности, в том числе при локализации сообщений.

Ошибки missing/null/типов, дат и Nested Error дают
`HydrationException` / `hydration_error`. Повреждённый JSON в JsonCast вызывает ошибку.
[Правила presence и defaults](defaults.md#section-2) действуют без дополнительных настроек.

`constructor_value_mismatch` означает расхождение входа с фиксированным значением
конструктора. [Проверки constructorValue](constructor-values.md) указывают свойство
целиком; значения и внутренние ключи массивов в новую диагностику не включаются.
