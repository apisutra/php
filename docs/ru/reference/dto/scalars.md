# Скаляры, union и диапазоны <a id="section-1"></a>

Общий Strict без реестра: `new HydrationConfig(policy: new RulePolicy(scalars: ScalarPolicy::Strict))`. Модель может явно переопределить его через `#[DtoHydrate(scalars: ScalarPolicy::Legacy)]`; остальные приоритеты описаны в [конфигурации](configuration.md).

## Автокаст по declared type <a id="section-2"></a>
В режиме Legacy ядро применяет безопасное приведение по объявленному типу свойства.
Strict задаётся отдельно внешним набором и имеет более узкие правила ниже.

Типовые кейсы:
- `"12"` -> `12` для `int`
- `"12.5"` -> `12.5` для `float`
- `"true"` / `"false"` / `"1"` / `"0"` -> `bool`
- `42` -> `"42"` для `string`

Это работает как встроенный fallback и не заменяет `#[Cast]`.
Если формат провайдера нестандартный или нужна особая логика — используйте явный `#[Cast(...)]`.

## Policy и строгие типы <a id="section-3"></a>

Политика выбирается по [приоритетам внешнего набора](field-rules.md#section-4).

| Цель при `ScalarPolicy::Strict` | Допустимый вход |
| --- | --- |
| int | PHP int |
| float | PHP float; int от −2^53 до 2^53 включительно с точным расширением |
| bool, true, false | Соответствующий bool/literal |
| string | Только строка, включая пустую |
| scalar union | Сначала точная ветвь с сохранением типа; затем расширение int → float |
| mixed | Любое значение |

Строки с числами и bool не становятся числами в strict. Переполнение int сохраняет
reason `integer_out_of_range`, прочие несовпадения — `invalid_field_type`.
Nullable проверяется отдельно; DateTime и enum сохраняют встроенные преобразования.
Результаты casts тоже проверяются до reflection. `ScalarPolicy::Legacy` разрешает
scalar conversions. Набор по умолчанию использует Legacy.

## Большие целые в ответах <a id="section-4"></a>

Целочисленный JSON-литерал вне диапазона PHP int автоматически сохраняется строкой
с точными цифрами. В пределах диапазона он остаётся int. Это работает в стандартном
разборе ответа, `ProviderResponse::json()`/`jsonStrict()` и вложенном JSON через
`JsonCast`. Настройка клиента не требуется.

Например, `{"id":9223372036854775808}` на 64-bit PHP даёт строку
`"9223372036854775808"`. Для идентификатора в DTO используйте `string` или `int|string`:

```php
use ApiSutra\DataTransfer\AbstractDto;

final readonly class OrderIdentifierDto extends AbstractDto
{
    public function __construct(public string $id) {}
}
```

В Legacy `string` также принимает обычный целочисленный ID; `int|string` сохраняет int для
обычного JSON integer и string для большого. Mixed и массивы сохраняют результат
декодирования. Если объявлен `int`/`?int`, число вне диапазона даёт `hydration_error`
вместо ограничения PHP_INT_MAX/MIN. Для новых ошибок доступен
[безопасный путь поля](../results/errors.md#section-12).

JSON-строки остаются строками при разборе. Дроби и экспоненциальная запись по-прежнему
декодируются как float: точная decimal-арифметика не предоставляется. Тип float или
FloatCast выбирает приблизительное представление. Уже округлённые сервером или
пользователем числа SDK не восстанавливает. При последующей отправке строковый ID
остаётся JSON-строкой; преобразования строки в числовой литерал автоматически нет.

Это изменение поведения: большие целые прежде могли возвращаться как float.
Проверьте DTO с int-полями, пользовательские обработчики json() и старые фикстуры.
Приблизительную арифметику выбирайте явно; для идентификаторов сохраняйте строки.
